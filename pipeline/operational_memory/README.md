# Operational Memory Ledger

This directory is the pipeline's durable repair manual.

- `occurrences/*.json` — immutable per-preflight, render, quality-warning, and telemetry evidence. One file per run/incident prevents concurrent renders from fighting over one append-only file.
- `solutions.json` — curated root causes, repair actions, fix commits, verification requirements, and safe-auto-fix boundaries.
- `prevention_rules.json` — machine-readable prevention contracts referenced by `pipeline/preflight.py` and its regression suite.
- `incidents.json` — materialized incident clusters generated by `pipeline/operational_memory_analysis.py`.
- `index.json` — causal solution verification, recurrence, warning, advisory, and performance scorecard.
- `action_queue.json` — ranked operational follow-ups generated from current evidence.

## Production commands

```bash
python3 pipeline/record_operational_run.py build/<slug>
python3 pipeline/operational_memory_analysis.py
python3 pipeline/preflight.py build/<slug>
python3 pipeline/package_integrity.py snapshot build/<slug>
```

`pipeline/operational_memory.py` remains the compatibility API for occurrence storage and historical tooling. New production workflows use `record_operational_run.py` and `operational_memory_analysis.py` so multiplicity and solution attribution remain causal.

## Authority boundary

The system may automatically apply only repairs explicitly marked `safe_to_auto_apply` and implemented as deterministic field normalization. It may not rewrite narration, political meaning, science claims, user-approved concepts, or visual direction. Unsafe or creative repairs block dispatch with a known solution reference.

## Lifecycle

`observed -> diagnosed -> repaired -> verification pending -> verified -> prevention rule`

A solution is curated by a human or reviewed code change. Evidence can increase or decrease its confidence, but the ledger never promotes a creative rule by itself. Lifetime recurrence counts remain visible; current state is determined by whether the latest verified event follows the latest recurrence.
